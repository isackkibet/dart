Firebase Storage Upload Pipeline — gcloud CLI + 4 Test Videos Seeded (Module A: Short Video Engine):
Established the full admin upload pipeline using the Google Cloud CLI:

Upload flow: gsutil cp {file} gs://yohlab.firebasestorage.app/videos/raw/{uid}/{filename}. Lesson learned: gsutil does NOT auto-set Firebase download tokens — uploads succeed in Storage but the URL is inaccessible from Flutter without patching. Fixed by PATCHing each object's GCS metadata via the Storage REST API to inject firebaseStorageDownloadTokens: {uuid}, then constructing the canonical download URL.

Cloud Function verification: processVideoUpload (europe-west2) auto-triggered on each upload. Required a matching Firestore videos/{docId} document with rawPath to exist before the Storage file is created — the CF pattern listens for Storage object.finalize and reads the Firestore doc by matching path. CF set status: live and hlsUrl on each doc.

Docs seeded: 4 documents in videos collection, each with status: live, hlsUrl: [download-url], ownerUsername: "kamaudavid", ownerId: [uid], createdAt: Timestamp, broken: false. Videos: Panda, Dance challenge, Animals compilation, Football highlights.

Creator Profile — users Collection Fallback (Module A — Creator UX):
Root cause: creatorProfiles/{uid} documents are auto-generated by analytics/follow events but contain only tracking counters — no displayName, username, or photoUrl. The full user profile lives in users/{uid} under different field names (firstName, lastName, userName, profile_picture, followersCount). Result: creator profile screen showed raw UID or "Creator" string.

Fix 1 — watchCreatorProfile() / getCreatorProfile(): Both methods now check if the returned creatorProfiles doc is missing or has an empty displayName. If so, they fetch users/{uid} and either (a) construct a full model via CreatorProfileModel.fromUserMap() when the profiles doc doesn't exist, or (b) deep-merge via displayFieldsFromUserMap() when the profiles doc exists but has empty display fields.

Fix 2 — CreatorProfileModel.fromUserMap(uid, map): New factory. Maps firstName + lastName → displayName, userName → username, profile_picture → photoUrl, followersCount → followerCount. Handles null-safety throughout with as String? ?? '' pattern.

Fix 3 — CreatorProfileModel.displayFieldsFromUserMap(map): Static helper returning a Map<String, dynamic> of just the display fields — used to merge into an existing partial creatorProfiles map without overwriting metrics (followerCount, videoCount, etc.).

Fix 4 — Profile header UI: Shows displayName ("David Kamau") as primary label. If username non-empty, renders @kamaudavid as a secondary handle below in white54. Fallback chain: displayName → username → userId. Never shows hardcoded "Creator" string or raw UID.

Firestore patch: creatorProfiles/DQWdtHDVYKQGZ5c8DcVf216pU6g1 patched with displayName: "David Kamau", username: "kamaudavid", photoUrl, bio: "" so the primary path returns immediately without the users fallback round-trip.
Broken Video Protection — Network Errors No Longer Mark broken=true (Module A):
Root cause surfaced: During a network outage while the app was open, ExoPlayer emitted SSL handshake failures for all 4 videos. VideoPlayerWidget._initVideo() caught these in its generic error handler and called onPlaybackError which in turn called VideoRepository.markVideoAsBroken(id) — writing broken: true to all 4 Firestore docs. When the network recovered, the feed remained empty because every video passed v.isPlayable => !broken && hlsUrl.isNotEmpty as false.

Fix — split error handling into transient vs permanent:
  • _showError() — sets _failed = true for transient UI error; does NOT call onPlaybackError — no Firestore write
  • _fail(reason) — calls onPlaybackError → markVideoAsBroken in Firestore — only for real content errors
Error classification: if the exception message contains ssl, socket, connection, network, timeout, or host → call _showError() only. All other errors (codec failure, bad URL format, 404) → call _fail().

Recovery: All 4 video docs reset to broken: false via Firebase Console.
Swipe-Up Gesture Fix — HitTestBehavior.translucent (Module A):
VideoOverlayWidget renders a GestureDetector over the creator info (bottom-left) area. The default HitTestBehavior.deferToChild (opaque on a Column) was consuming vertical swipe events within the bounding box of the creator text, preventing them from reaching the underlying PageView. Users swiping up on the creator info area saw no transition.

Fix: added behavior: HitTestBehavior.translucent to the creator info GestureDetector. Touch events now fall through to the PageView for vertical swipes, while horizontal taps still route correctly to Navigator.pushNamed('/creator-profile'). Tested on device: swipe-up from any position on the feed now reliably advances to the next video.
createdAt Field — Firestore orderBy Silent Exclusion Fix:
Firestore's orderBy('createdAt', descending: true) silently excludes any document where the createdAt field is absent or null — no error, zero docs returned. All 4 seeded video documents were missing createdAt after the initial upload (the Cloud Function sets it only on first trigger; manual uploads without a matching pre-existing Firestore doc skip the CF). Patched all 4 docs with createdAt: Timestamp("2026-06-25T09:00:00Z"). Feed immediately returned all 4 videos.
