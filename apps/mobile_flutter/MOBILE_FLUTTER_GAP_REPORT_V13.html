Phase 5H — Ad Billing & Budget Enforcement Cloud Functions Pack (Module J: Ads Engine)
Four production Cloud Functions files written, built, tested, and committed as dcfbfb9:

1. adBillingTypes.ts — Shared interfaces: AdCampaign, AdEngagementEvent, BillingResult, AdEngagementType. Added budgetStatus?: string field after initial build surfaced TS2339 error.

2. adBillingCalculator.ts — Pure billing math (no Firestore): calculateAdBilling(campaign, event) dispatches on event.type. Impression → CPM path: uses costPerImpression if set, otherwise falls back to cpm / 1000. Click → CPC path: uses costPerClick first, falls back to cpc field. roundCurrency(value) rounds to 2 decimal places via Math.round(v * 100) / 100. Pure function — zero side effects, fully testable without mocking.

3. adBillingProcessor.ts — adBillingProcessor Cloud Function: onDocumentCreated('adEngagementEvents/{eventId}'), region europe-west2. Runs a Firestore transaction to enforce strict idempotency: reads adBillingProcessedEvents/{eventId} as the first action — if it already exists, returns immediately. Guard chain: campaign exists → campaign is active + deliveryEnabled → budget not already exhausted → calculate charge → cap chargeable amount to min(billedAmount, remainingBudget) → write adCampaigns update (spend, remainingBudget, budgetStatus, deliveryEnabled, status) → write adBillingProcessedEvents/{eventId} idempotency lock → write adBillingAuditLogs full record. Campaign auto-pauses when newSpend >= budget: status: 'paused', deliveryEnabled: false, budgetStatus: 'exhausted'.

4. campaignBudgetStatusUpdater.ts — Drift reconciler: onDocumentUpdated('adCampaigns/{campaignId}'). Recomputes remainingBudget and budgetStatus from budget - spend on every campaign write and patches back if stale. No-op guard: returns immediately if all three derived fields already match — prevents write loop. Ensures UI always reflects a consistent budget state even if adBillingProcessor and another writer race.

5. Firestore rules updated: Added two Admin-SDK-only collections: adBillingAuditLogs (allow read, write: if false) and adBillingProcessedEvents (allow read, write: if false). Rules compiled successfully against project yohpal-a3125 — deployment pending IAM fix (see below).

6. index.ts updated: Phase 5H export block added: export { adBillingProcessor, campaignBudgetStatusUpdater } from './ads/adBillingProcessor'.
