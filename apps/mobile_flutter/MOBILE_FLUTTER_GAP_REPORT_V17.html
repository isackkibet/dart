6 new Flutter files in lib/features/predictive/:

Hotfix 1 — VideoModel.fromMap: NoSuchMethodError on String-typed Firestore counts (commit ee52e0d):

Root cause: Legacy Firestore video docs store views/likes as String "0" instead of int. The expression (data['views'] ?? 0 as num).toInt() — the as num cast applies only to the literal 0, not to the runtime value. When a String arrives, .toInt() throws NoSuchMethodError: Class 'String' has no instance method 'toInt'. This crashed every preloadAround call on first swipe, flooding the log with repeated exceptions.

Fix: Added static int _parseInt(dynamic v) helper: if v is int → return v; if v is num → return v.toInt(); if v is String → return int.tryParse(v) ?? 0; null → 0. Both views and likes fields now route through this helper.
Hotfix 2 — Firestore equality filters silently dropped all 58 videos from the feed (commit e3b2257):

Root cause: .where('playbackReady', isEqualTo: true) and .where('processingStatus', isEqualTo: 'ready') were applied to the client-feed query in VideoFeedRepository. Firestore equality filters silently exclude any document where the field is absent — absence is not treated as false. All 58 legacy video docs predate these fields, so every query returned zero results and the feed showed blank.

Fix: Removed both Firestore-level field filters from suggestedFeed(), followingFeed(), and trendingFeed(). The existing _isReady() client-side guard (checks broken, visibility, URL presence) handles all filtering. Fetch limit raised 50 → 100 to accommodate all current docs.
Broken video investigation — 3 HLS-confirmed videos restored (Firestore admin script, run once):

Firestore contains 2,966 docs with broken: true. Investigation confirmed that 57 of these have fully intact HLS content in Storage (videos-hls/{videoId}/master.m3u8 + 360p/480p/720p playlists + .ts segments). Of those 57, three were incorrectly flagged broken: true after the app's reportBroken() fired on 403 errors before the Phase 1N Firebase auth-header fix. The HLS files were never actually broken — the URL access was the problem. Admin script unbreak_hls_videos.js (run once, deleted) cleared broken: false on those 3 docs. 54 of the 57 were already correct.
