Video Upload Pipeline — 4 Root-Cause Bugs Fixed (Module A: Short Video Engine):
A post-v9 debug investigation revealed that no videos ever appeared in the feed despite Storage uploads succeeding. Four compounding bugs identified and fixed:

Bug 1 — Wrong Firestore field name in CF: processVideoUpload was writing videoUrl: rawDownloadUrl but VideoModel.fromMap() reads data['hlsUrl'] (with data['hlsPath'] as fallback). hlsUrl was always "". Fixed: CF now writes both hlsUrl: rawDownloadUrl and videoUrl: rawDownloadUrl (backwards compat).

Bug 2 — isPlayable required .m3u8 extension: VideoModel.isPlayable checked hlsUrl.contains('.m3u8'). Since the HLS Cloud Run transcoder is an unimplemented stub, all uploaded videos have raw MP4 URLs. Every video was silently filtered out of the feed. Fixed: isPlayable => !broken && hlsUrl.isNotEmpty.

Bug 3 — ownerId missing from Firestore document: VideoUploadModel.toMap() wrote only userId but VideoRepository.getFollowingVideos queries ownerId whereIn creatorIds. The following-feed query always returned zero results. Fixed: added 'ownerId': userId to toMap().

Bug 4 — ISO string dates instead of server timestamps: Upload model stored createdAt as a Dart ISO string. Firestore composite indexes on (status, createdAt DESC) and (ownerId, status, createdAt DESC) expect Timestamp type; ISO strings cause type-mismatch silent failures in queries. Fixed: VideoUploadRepository.createVideoDocument() now overrides both fields with FieldValue.serverTimestamp().

Bonus — visibility was 'private': Changed default from 'private' to 'public' so videos appear in public feed queries. Also added missing initial fields (hlsUrl: '', views: 0, likes: 0, engagementScore: 0, hlsManifestUrl: '') to the initial document for schema consistency.

CF deploy successful — processVideoUpload(europe-west2) updated. Region confirmed correct (all project functions are europe-west2; the brief incorrect change to us-central1 was reverted before final deploy). tsc --noEmit: 0 errors. flutter analyze: 0 issues.
HLS Transcoding Pipeline — Architecture Audit (informational):
Investigation surfaced that real HLS transcoding has never been implemented. The blueprint calls for a Cloud Run video_transcoder worker (Python/FastAPI + ffmpeg ABR → .m3u8 + segments). The source exists at backend/cloud_run_workers/video_transcoder/main.py but is a TODO stub that returns {'status': 'queued'} without doing anything. ffmpeg_pipeline.py has a skeleton ffmpeg command missing quality ladders. TranscodingService.dart in Flutter calls a /videos/complete-upload endpoint that was never deployed — it is dead code.

The raw MP4 stopgap (Bug 1+2 fix above) is forward-compatible: when the real transcoder is built and writes a real .m3u8 URL to hlsUrl, isPlayable (isNotEmpty) will correctly pass it through. No rework needed when transcoder is implemented.
Chat Module — 2 Code Bugs Found Post-v9 (Module L: Chat Engine, ↓ 88% → 75%):
Code review during device E2E investigation surfaced two functional bugs in the Phase 6A chat implementation:

Bug C1 — No UI navigation entry to ChatListScreen: ChatListScreen.routeName = '/chat' is registered in router.dart but no button, bottom-bar tab, profile action, or notification tap navigates to it. Users cannot open the chat screen from the running app. Requires adding a nav entry (e.g. bottom bar icon, message button on CreatorProfileScreen, or notification-type route in NotificationInboxScreen).

The unread count badge in ChatListScreen will always show 0 for the recipient. Message delivery works; the badge does not.
