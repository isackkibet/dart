Architecture & Security Findings

AreaVerdictDetail
Authentication guard ❌ Missing Router has no auth guard. All 15 routes are accessible without a signed-in user. The features/auth/screens/ folder is empty — no LoginScreen exists. The app cannot sign in anyone.
Firebase configuration (iOS) ❌ Missing firebase_options.dart only contains the Android configuration. iOS and macOS entries are absent — the app will crash on iOS without them.
Firestore security rules ❌ Missing No firestore.rules file in the mobile or root directory. All collections are open by default. Must be set before any user data is written.
State management architecture ⚠ Partial Only VideoFeedController uses Provider. All other features have no state management layer — stub screens call nothing. Inconsistent: some features may need Bloc or Riverpod for stream-based features (chat, live).
Error handling in services ❌ Missing No try/catch patterns seen in stub services. Repository calls should wrap Firestore operations in try/catch and return typed Result or Either objects.
Video upload security ❌ Missing Firebase Storage rules not configured. No file-type validation or size limits on upload. Upload feature is entirely missing (see Module C).
Analytics service ✅ Good analytics_service.dart records events with server timestamp to Firestore videoEvents. Used by VideoInteractionService. Pattern is correct — extend to all other event types.
Dependency injection ⚠ Partial Services and repositories accept constructor arguments — good for testability. But Provider is only wired for VideoFeedController; no other services are in the widget tree.
image_picker / camera dependency ❌ Missing image_picker is not in pubspec.yaml. Video upload (the core creator action) is impossible without it.
HLS player library ⚠ Partial video_player package is used. Note: video_player on Android requires a format-compatible ExoPlayer; HLS works but some edge cases may need better_player or media_kit for buffering control.
