Phase 1R — Context Intelligence Engine (commit 12699bb):

8 new Flutter files in lib/features/context_intelligence/:
• models/context_snapshot_model.dart — Captures screen/video/creator context per page change: userId, currentScreen, videoId, creatorId, isFollowingCreator, hasActiveCoupon, hasCommerceTags, hasPoll, isLiveAvailable, canMessageCreator, metadata. All optional. Const-safe immutable model.
• models/context_action_model.dart — Represents a single rendered action: id, title, subtitle, type, route, priority, arguments. Const-safe. Used by engine, controller, and strip widget.
• services/context_intelligence_engine.dart — Evaluates ContextSnapshotModel → builds up to 7 candidate actions → sorts by priority desc → returns top 5. Actions: Ask AI (0.95, feed+videoId always), Shop (0.88, hasCommerceTags), Live (0.86, isLiveAvailable), Coupon (0.82, hasActiveCoupon), Poll (0.78, hasPoll), Chat (0.76, canMessageCreator), Ads Arena (0.52, always). Each action id encodes videoId/creatorId for analytics uniqueness.
• services/context_action_engine.dart — execute(BuildContext, action) and executeWithNavigator(NavigatorState, action). The second overload is required to avoid the BuildContext-across-async-gap lint — the controller captures Navigator.of(context) before any await and passes the NavigatorState here.
• repositories/context_analytics_repository.dart — Writes to contextActionEvents Firestore collection via record({userId, actionId, eventType, metadata}). Fields: userId, actionId, eventType, metadata, createdAt (serverTimestamp). Three event types: impression, acceptance, dismissal.
• controllers/context_intelligence_controller.dart — ChangeNotifier orchestrator. updateContext(snapshot): evaluates engine → records impression per action → notifyListeners. executeAction({context, userId, action}): captures navigator before await → records acceptance → navigates. dismissAction({userId, action}): removes from list → records dismissal → notifyListeners.
• widgets/dynamic_context_action_card.dart — Card with Color(0xEE101020) dark background, Icons.auto_awesome purple icon, title, subtitle, and an X dismiss button. Calls executeAction on tap and dismissAction on close.
• widgets/context_action_strip.dart — Positioned(left:12, right:72, bottom:96). Reads top 2 actions from ContextIntelligenceController and renders a column of DynamicContextActionCard.

Feed query fix — hlsLowUrl filter replaces broken-field filter (commit 2964c3b):

Root cause: The feed query used .where('broken', isEqualTo: false) which Firestore evaluates as "broken field exists AND equals false" — docs without the field are excluded. 50 HLS-transcoded videos had no broken field at all, so the feed returned only legacy raw-MP4 docs that 404'd on ExoPlayer. Additionally, hlsUrl in Firestore pointed to videos-raw/...mp4 (the raw upload bucket), not the HLS playlist, so even docs that passed filtering played raw MP4 which ExoPlayer cannot decode.

Fix: Feed query changed to .where('hlsLowUrl', isGreaterThan: '').orderBy('hlsLowUrl') — this targets exactly the ~50 transcoded docs with a real HLS playlist URL. No composite index required (single-field inequality). URL resolution priority in VideoModel.fromMap() updated to prefer hlsLowUrl → hlsStandardUrl → hlsUrl → videoUrl.
