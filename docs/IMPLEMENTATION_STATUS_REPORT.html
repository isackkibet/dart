01

Executive summary

Of the original review's 40 findings, 7 are fully closed and 3 are partially mitigated — concentrated almost entirely in the Critical, money-and-fraud bucket, which was the right thing to fix first. The High-severity bucket, which is mostly UX reliability and test coverage, is essentially untouched: 0 of 13 fully fixed. Two features not in the original review at all — Google and Apple Sign-In — were built from scratch this cycle.

Net-new features (SSO)

The work that happened maps almost exactly to one branch of the release plan the team wrote in response to the review (apps/mobile_flutter/docs/): Track 1.0B — Money, Security & Wallet Reconciliation was executed in full. Tracks 1.0A (account/navigation/observability), 1.0C (feed/live UX recovery), and 1.0D (cleanup/tests/release gate) were not started, with one exception — sign-out, which was technically scoped under 1.0A, got built as a standalone request and is done. On top of that plan, a second wave of work went well beyond it: Google and Apple SSO, a full login/signup visual redesign, and a Terms & Conditions requirement — none of which were asked for by the original review, but which materially improve the auth surface anyway.

The net effect: the fraud-and-money risk this app carried is substantially reduced — gift amounts are now server-validated, rewarded-ad spoofing has a real mitigation, Firestore's most exploitable write rules are closed, and users finally get feedback when a wallet action completes. But the app is no closer to General Availability than the original review's headline blockers imply — the crashing Analytics route, the complete absence of crash reporting, hardcoded production infrastructure, and password reset are all still exactly as they were found. Anyone reading only "9 Critical → 4 fixed" without reading which 4 would over-estimate readiness.

02

Authentication: full progress

Requested separately because more happened here than anywhere else in the codebase this cycle. Organized by what's real and working versus what's still exactly as the original review found it.

Shipped and verified working

Sign-out — Critical finding #1, closed
creator_profile_screen.dart · _LogoutButton

Confirm dialog → AuthController.logout() → pops the nav stack to root so AuthGate's reactive swap to LoginScreen is actually visible, not hidden under a pushed route. This was previously implemented but fully unreachable — logout() existed with zero call sites anywhere in the UI.

Google Sign-In — new capability
auth_repository.dart · signInWithGoogle()

Real credential exchange via google_sign_in + Firebase's GoogleAuthProvider, not a stub. Creates users/creatorProfiles Firestore docs only when Firebase reports a genuinely new account, so a returning Google user is treated as login, not signup.

Apple Sign-In — new capability
auth_repository.dart · signInWithApple()

Nonce-secured per Apple/Firebase's required flow. Apple only ever returns the user's name on their very first authorization ever — that's captured and saved immediately, since it's unrecoverable after. Hidden on Android in the UI, where sign_in_with_apple has no native support without server-side relay infrastructure this project doesn't have.

A regression was introduced, then caught and fixed in the same cycle
auth_repository.dart · signOut()

Adding Google sign-out to signOut() put it before the real Firebase sign-out call — if the Google call threw for any user who'd never used Google Sign-In, Firebase sign-out never ran, and logout silently stopped working end to end. Fixed by making the Google cleanup best-effort and non-blocking; Firebase sign-out now always executes regardless.

Terms & Conditions — partially closes High finding #1
signup_screen.dart, terms_and_conditions_screen.dart

A real, readable Terms page, gated behind a required checkbox before account creation — the original "no ToS/Privacy link" gap is now half-closed (ToS exists; there's still no separate Privacy Policy link).

Confirm-password field — Low finding, closed
signup_screen.dart

With an actual mismatch check on submit, not a decorative field.

First/last name split, full visual redesign
login_screen.dart, signup_screen.dart

Display name is now first + last name, joined for the backend call. Both screens moved off a boxed card onto a full-bleed background with a shared brand mark and SSO tile row, for visual consistency with each other.

07

Work done beyond the original review

Not findings from the audit — new capabilities and one bug the audit didn't have visibility into, since it never inspected the Cloud Functions backend.

  • Google + Apple SSO, described fully in §2.
  • A real backend bug, found and fixed: mpesaPayoutTrigger.ts was reading and writing a wallets/{uid} collection that nothing else in the codebase ever populated — every real balance lives in walletBalances/{uid}. Every payout request was silently failing "insufficient balance" regardless of a creator's actual balance. Repointed to the correct collection.
  • Login/signup visual redesign: both screens moved off a boxed card onto a full-bleed themed background, added a shared brand mark, an "or continue with" divider, and the SSO tile row — a UX pass, not a functional fix.
  • Display name split into first/last name on signup.
08

What to prioritize next

In order — each depends less on the ones after it than the reverse.

  1. Crash reporting. Nothing else on this list will be observable in production without it, and it's the smallest remaining Critical item.
  2. Fix the Analytics route crash. A one-line fix (profile_hub_screen.dart:100) sitting on one of five primary navigation destinations.
  3. Password reset. The button already exists and is discoverable — it just doesn't do anything yet. This is now the most visible remaining gap in the auth flow this cycle's work built out.
  4. Friendly auth error messages. Small, contained, and was already scoped and half-designed in the team's own 1.0A plan — never built.
  5. Environment config for hardcoded URLs. Blocks safely rotating infrastructure without an app-store release, and blocks having a real staging environment at all.
  6. Wire Search and Live Discovery into navigation. Both backends already work — this is the highest user-value-per-hour item left on the entire original list.
  7. Add test coverage for what just shipped. The gift-purchase Cloud Function, wallet reconciliation flow, and both SSO paths are new, money- and auth-adjacent, and currently have zero automated coverage.
