2Enterprise Health Model

Built at lib/platform/mission_control/health/enterprise_health.dart. Every module publishes an EnterpriseHealth snapshot to the Firestore missionControlHealth collection.

enum HealthStatus { healthy, warning, critical } class EnterpriseHealth { final String module; final HealthStatus status; final double availability; // 0–100 % final double latencyMs; final int activeUsers; final int incidents; bool get isHealthy => status == HealthStatus.healthy; bool get needsAttention => status != HealthStatus.healthy; }
3YohPal Digital Twin

Built at lib/platform/mission_control/digital_twin/yohpal_digital_twin.dart. Aggregates live health across all modules into a single ecosystem state. Mission Control streams this object in real time.

class YohPalDigitalTwin { final List<EnterpriseHealth> modules; final DateTime lastUpdated; double get ecosystemAvailability => modules.isEmpty ? 0 : modules.map((m) => m.availability).reduce((a,b) => a+b) / modules.length; int get totalActiveUsers => modules.fold(0, (s, m) => s + m.activeUsers); int get totalIncidents => modules.fold(0, (s, m) => s + m.incidents); List<EnterpriseHealth> get criticalModules => modules.where((m) => m.status == HealthStatus.critical).toList(); HealthStatus get ecosystemStatus { if (modules.any((m) => m.status == HealthStatus.critical)) return HealthStatus.critical; if (modules.any((m) => m.status == HealthStatus.warning)) return HealthStatus.warning; return HealthStatus.healthy; } }

9Digital Twin Synchronisation Events

Every module publishes these events. Mission Control consumes all of them to maintain a live ecosystem state without polling.

  • ModuleHealthChanged Module availability, latency, or incident count updated
  • WalletUpdated Wallet balance or transaction volume changed
  • IncidentRaised P0/P1/P2 incident opened — correlates across all modules
  • DeploymentCompleted Module release successfully deployed to production
  • RolloutPaused Progressive rollout halted — Mission Control takes control
  • RolloutResumed Rollout resumed after incident resolution or manual approval

11Phase 19 Success Criteria
  • One Mission Control for every YohPal module — no per-module operational console
  • Shared platform services monitored centrally via missionControlHealth
  • Infrastructure monitored centrally — Firestore, Cloud Run, FFmpeg, Mediasoup
  • Wallet monitored centrally — balance, transaction success, fraud alerts
  • AI monitored centrally — BrainGateway success rate and latency
  • Cross-module incidents correlated via event bus — one incident, ecosystem-wide view
  • Predictive recommendations generated from live telemetry — no manual monitoring required
  • Executive dashboard updates in real time from YohPalDigitalTwin stream

Strategic Recommendation

Phase 19 should be the highest architectural layer of the YohPal ecosystem — the permanent enterprise operations layer. Rather than every application having its own operational console, YohPal has one enterprise Mission Control that supervises Live, Jobs, Hustle, Market, Wallet, Brain, YCIOS, and every future application. It becomes the single operational command centre for engineering, operations, security, finance, product, and executive leadership simultaneously.
