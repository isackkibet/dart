Platform service contracts — abstract interfaces all modules implement against:

abstract class YohPalPlatformService { Future<void> initialize(); Future<void> login(); Future<void> logout(); Future<void> refreshSession(); } class YohPalIdentity { final String uid; final String role; // 'viewer' | 'creator' | 'business' | 'admin' final String displayName; final String? creatorId; final bool verified; const YohPalIdentity({ required this.uid, required this.role, required this.displayName, this.creatorId, this.verified = false, }); } abstract class YohPalWalletService { Future<double> getBalance(); Future<void> transfer({required String toUid, required double amount}); Future<void> withdraw({required double amount}); Future<void> deposit({required double amount}); } abstract class NotificationHub { Future<void> push({required String userId, required String title, required String body}); Future<void> email({required String to, required String templateId}); Future<void> sms({required String phone, required String message}); Future<void> inApp({required String userId, required Map<String, dynamic> payload}); } abstract class YohPalBrainGateway { // Every module calls this — never calls AI providers directly Future<dynamic> execute({required String task, required Map<String, dynamic> params}); }

Strategic Recommendation

Phase 12 is elevated to an enterprise architecture programme. Its deliverable is not a feature — it is the architectural foundation on which every current and future YohPal application runs. This eliminates duplication, reduces maintenance cost across the portfolio, and delivers a consistent user experience. Once the platform layer exists, adding a new YohPal module becomes a matter of consuming shared services rather than rebuilding core infrastructure.
