6Outstanding Work — 9 Items Required Before Certification
  • Module migration adapters — 6 of 7 modules still pending
    Live, Hustle, Jobs, Market, Wallet, Brain all need a YohPalModuleMigrationAdapter implementation. YCIOS is the only completed reference. Without these, allRequiredModulesRegistered returns false.
    High
  • CI/CD pipeline — no automated test run on push
    flutter test and flutter analyze run locally only. A CI pipeline (GitHub Actions or equivalent) must run the full suite automatically on every push to flutter_app before certification can proceed.
    High
  • Concrete YohPalOS implementation
    YohPalOS is an abstract class. No FirebaseYohPalOS or equivalent concrete class exists yet. The OS cannot be wired into the app without it.
    High
  • Event bus live proof — Firestore enterpriseEvents populated
    Required for Phase 21 evidence gate. Each module must publish at least one YohPalEnterpriseEvent to the enterpriseEvents collection in production.
    High
  • Mission Control dashboard — all 7 modules visible live
    Required for Phase 21. Screenshots must show real-time health status for Live, Hustle, Jobs, Market, Wallet, Brain, YCIOS via the YohPalDigitalTwin stream.
    High
  • Automation policy registration at startup
    The 7 automation policies defined in Phase 20 must be registered via YohPalAutomationEngine.registerPolicy() at app startup. No concrete engine implementation exists yet.
    Medium
  • Approval workflow proof — at least one ApprovalRequest in Firestore
    Required for Phase 21. A complete approve() or reject() flow must be demonstrated for a high-impact action (rollback, wallet freeze, or equivalent).
    Medium
  • flutter analyze — full project scope (lib/)
    analyze has only been run against lib/platform/ sub-directories. A full project-wide run is required for Phase 21 evidence and Phase 22 certification.
    Medium
  • Phase 22 evidence package — 10 items, signed document
    All 10 Phase 21 evidence items must be submitted, independently reviewed by the Governance Board, and the Phase 22 certification document signed by all 6 roles before the Enterprise Platform Certificate can be issued.
    Medium

8Permanent Constraints

Financial Compliance — Non-Expiring

All client-side wallet write operations (credit() and debit()) throw UnsupportedError in FirebaseWalletService. Writes are web-only via Cloud Functions. This is a permanent architectural constraint that does not change with any future phase, certification, or governance decision.

Firestore & Storage Rules — Never Deploy via Claude

Firestore and Storage rules are never deployed by this tooling. The user manages and deploys rules directly. Full firebase deploy --only functions is blocked (would delete 35 live production functions). Only targeted single-function deploys are permitted.
